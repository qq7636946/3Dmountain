# 卡牌 → 地球 交接卡頓：稽核與提案（2026-10-24）

**狀態：只做量測與稽核，尚未改任何頁面程式或畫面。** 等你確認提案後才動。

## 1. 結論

1. **卡住的主因是交接時機，不是轉場畫面。** 交接要等橋段彈簧停穩（transition 到 1）才觸發：index1-1 約 350 ms，index1-5 約 770 ms。這段時間的滾輪格被吞掉，之後地球才開始下載（`finnovation-world.js` 與約 2.1 MB 貼圖）並掛上。
2. **量測（1440×900 桌機，時間 0 = 卡牌停住）：** index1-1 星球開始動 **425–441 ms**；index1-5 **892 ms**。把地球先掛好（`--pause`）仍停 408 ms，所以等待閘門本身就是主因之一，跟下載無關。
3. **網路或 CPU 慢時，載入變成第二個主因：** 4G 600 ms；Fast 3G 883 ms（貼圖估計還要 10 秒以上，這段星球是平面色）；CPU 4× 783 ms，交接瞬間還有一個 419 ms 的長任務。
4. **現行地球交接本來就是連續的 WebGL**（同一條滾輪時鐘驅動）。換成「刷過去」的轉場不能解決時機問題，反而會是新的視覺設計。
5. **建議：** F2（交接門檻）與 F1（提前載入）一起做，加上 F3（不丟滾輪）。F4（貼圖未到位的呈現）與 F5（交接瞬間的同步工作）需要你決定或再量測。**目前沒有改任何程式或畫面。**

## 7. 提案（尚未實作）

- **F1 提前載入**（風險低，畫面不變，但改變下載時機）。在橋段開始時（index1-1 約在卡牌停住前 1.7 秒）就開始 `loadWorld()`，不再等橋段停穩或靜止 900 ms。代價：約 2.1 MB + 約 0.1 MB（JS、CSS、CDN 模組）會在最後一章就開始下載，行動網路要考慮流量。回復：還原觸發條件。
- **F2 交接不等彈簧停穩**（風險中，改變卡牌停下瞬間的動態）。門檻從 `amount ≥ .999` 降到 `.97`：時間軸上橋段在停住前已到 .978，所以交接大約就在卡牌停住的那一刻。影響：星球提早約 350 ms 開始動，兩段會重疊，需要看動態確認。index1-5 的門檻要另外量測。
- **F3 不丟滾輪**（風險低）。地球還沒掛上時先記下這一格的量，掛上後套用。影響很小，只是不再丟格。
- **F4 貼圖未到位時的呈現**（需你決定）。(a) 等貼圖到位才交接：沒有跳變，但可能多停一小段，取決於網路。(b) 立即交接，星球貼圖淡入（約 0.5 秒）。
- **F5 交接瞬間的同步工作**（風險中，只改執行方式，不改畫面）。先用 profiler 確認 419 ms 長任務是什麼，再把 `enter()` 的同步排版與文字排版的小步驟分批，避開卡牌停住的那一刻。
- **D「地球 → 海洋的 WebGL 刷過去」**（你提的備案）：不建議作為第一步。現行地球交接已是連續的，刷過去會變成新的視覺設計，需要參考圖與你確認樣子。若要做，另出提案。
