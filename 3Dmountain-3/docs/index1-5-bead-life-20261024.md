# index1-5 第一塊散開的水滴：停住時也會「律動」（2026-10-24）

客戶：「向這邊時候水滴還會律動，滾下去就不動了 雖然我知道這是兩個不同水滴 但圖二這個可以假裝律動讓銜接上不會差太多嗎」。
圖：[改前／改後、英雄 → 主珠交接](index1-5-bead-life/before-after-20261024.jpg)。

## 為什麼滾下去就不動
- 圖一（旅程約 .7）中間那顆是英雄水珠（SDF），表面那層 Codrops 光斑與虹彩雜訊跟著時鐘流動。停住時每 1.5 秒約 **29%** 的像素在變。
- 圖二（旅程約 .9）的水滴是散開的珠子（instanced），位置、形狀全部只看捲動位置。捲動一停，**0%** 在變。
- 另外：一捲動，英雄自己的呼吸時鐘其實就停了。所以圖一看到的「律動」，就是那層流動的光斑和虹彩。

## 改了什麼（只動 index1-5）
新的建置小幫手 `prototypes/index1-5/bead-life-build.cjs`，由 `build.cjs` 套用。共用的 `js/main.js` 沒動，其他頁不受影響。
1. **光斑、虹彩一起流動**：珠子穿上英雄水珠同一層光斑，虹彩也改用同一張會流的雜訊。uniform 直接共用英雄的，所以英雄的「光斑」「噪點速度」一調，珠子也跟著變。
   - 主珠（接英雄班的那顆）用的是和英雄完全同一張花紋，交接那一格不跳。
   - 其他顆各自錯開，不會像印出來的。
   - 原本虹彩遮罩在珠子上留的那道硬接縫，順便消失了。
2. **呼吸與表面波**：用英雄的同一條公式、同一組數字，速度很慢、幅度很小。主珠和英雄同相，其他顆錯開。「減少動態」模式下不呼吸。
3. **外框變圓**：珠子的網格細分 3 → 10。原本大顆珠子（半徑 180–365 px）的外框看得到折角，現在沒有了。
4. **窗光淡入**（客戶同日：「讓主珠接手後那圈窗光淡入」）：
   - 先量過：接手那一格只有「光帶」不同（珠子 .16、英雄 0），黑卡、粗糙度、亮核、邊光都和英雄一樣。
   - 所以每顆珠子的光帶都從英雄的量開始：主珠看它離最近那顆碎片多遠，芽看自己離本體多遠，分開約一個自己的半徑，才長到珠子原本的量。
   - 主珠接手那一格是 0。到圖二的位置（.9）約 .56。約 .97（大約一格滾輪）全滿。再往鏡頭靠近的樣子沒變。
   - 一樣只看捲動位置，往回捲照樣倒著走。對照圖：[窗光淡入 0／.6／1.2](index1-5-bead-life/ring-fade-20261024.jpg)。
- 位置、時間點、飛行軌跡、光芒，全部沒動。捲回去照樣倒著走。

## 驗證
- 停在旅程 .9：主珠區域每 1.5 秒 **31–37%** 的像素在變（改前 0%，英雄約 30%）。
- 英雄 → 主珠交接：時鐘停住，前後兩格比對，花紋連得上。
- 近鏡頭（1.05–1.4）：外框圓了，光斑自然，沒有破綻。
- 手機版面、減少動態、真實滾輪 0 → 1.08 再停 3 秒，都跑過。主控台錯誤 0。
- GPU（同一頁、三輪交錯 A/B，1440×900 @2x）：旅程 .9 是 1.17 → 1.22 ms／幀，1.15 是 1.19 → 1.23 ms／幀，約 +0.05 ms。
- 窗光淡入：主珠的淡入量在 .83 是 0、.85 是 .10、.87 是 .28、.9 是 .56、.95 是 .94、1.0 是 1。交接前後時鐘停住比對，窗光不再跳出來，主控台錯誤 0。
