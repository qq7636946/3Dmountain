# index1-5 峽谷卡片修補（backlog A-32，2026-10-24）

客戶核可「三項大的視覺改動…都處理」。範圍：一鏡到底（p 約 4.45–4.74）的烘焙峽谷卡片，檔案只動 `prototypes/index1-5/opening-portal.js`。
備份：`_archive/backups/index1-5-portal-fix-20261024/`（opening-portal.js、opening-world-build.cjs、build.cjs 修改前版本）。圖與量測：`docs/index1-5-portal-fix-20261024/`。

## 原因
卡片原本是一張 4 px 格子的 2.5-D 網格（頂點放在烘焙深度上）。網格遇到深度斷層（山壁對天空、岸對遠水）時，跨斷層的三角形被拉成「橡皮布」，這些格子被畫成開場的天色：
- 山壁剪影是格子階梯、壁面裡一格格天色破洞、天上漂著亮岩碎片、岸被打斷、壁腳鋸齒。
- 水界線是頂點內插，所以壁腳也是階梯。

## 做法（portalFix 1，預設）
卡片改成**逐像素光線步進**（取代網格；烘焙本身沒變，仍是切換點姿勢的一張顏色＋深度）：
1. 每個像素把視線轉到烘焙鏡頭空間，在深度圖上依「畫面空間等距」（透視正確）取樣 `fixSteps` 次，找到「射線從表面前方走到表面後方」的第一格，再二分精修 `fixRefine` 次，精度小於 1 個貼圖格。剪影與水界線因此是逐像素的。
2. 精修後若落在**深度斷層**上（兩側距離差超過 `fixJump` 比例）就不是命中：射線是從前景邊緣後面滑過去（網格以前撕開的洞）。改取邊緣旁的背景，往背景側退 `fixPush` 格、取 `fixFill` 級 mip 的柔化色，所以補出來的是背景的延伸，不再是開場的天。
3. 命中的顏色做深度雙邊雙線性（只用和命中同深度的貼圖格），暗壁不會有淺色天邊。
4. 射線在畫框前面離開、或一開始就在表面後面的像素 `discard`，露出真正的背景與海。
5. 逐像素寫入深度（河面維持贏過活湖浪尖的優先權）、逐像素水界線、空氣透視／遠景板淡入／畫框邊淡出都沿用舊公式。
`window.__OPENING_PORTAL__`（只讀）可看 `bake.ms`、`state`、`uniforms`；`?portal=debug` 或 `portalDebug=1` 把補出來的像素塗洋紅（`2` 再把「這裡沒有卡片」塗綠）。

## 切換點（4.735 → 4.745）
- 山壁剪影、山口、天空逐格對得上：6×4 格平均 L* 差，上兩列（天與壁）全在 ±1.0 以內，新舊一樣（`cut-diff-*.txt`）。
- 沒有解決：下兩列（水面、壁腳）差 ±10–17 L*，新舊都有。原因是卡片的水是一張靜止烘焙圖，而真河的波形、流光線隨時間變，兩次截圖的水面中位亮度本來就會差到 ±10 以上（我重烘卡片後方向反過來）。這是 A-36（靜止水面、虛線流光線）；A-34（霧、明暗斜率）、A-35（遠山身分）也沒動。

## 已知限制
- 剪影是單像素硬邊（卡片本身在畫面空間沒有 MSAA；烘焙貼圖約 0.85 格／像素），放大 3× 可見 1 px 階梯，真實峽谷有 MSAA 所以略平滑。要再平滑可對斷層像素多射 2–4 條偏移射線（尚未做）。
- 補洞是「背景延伸」，不是真資料；p 4.5 以前、霧很厚時看不出來，若之後把霧提早散掉（A-34），山脊後面的補洞會更容易被看到。
- 細於一個步進的薄物（單像素尖峰）可能在某些角度被跳過而閃爍；用 `fixSteps`／`fixRefine` 加密可緩和。
- 水界線仍是整像素 discard（沒有 alpha-to-coverage）。
- 無頭 Chrome（RTX 4070）數字，沒有實機手機的 GPU 時間；手機為 `fixSteps`×0.75＝27 步＋7 次精修。
- 工具：`tools/measure.probe.cjs`（洋紅比例，經 probe.cjs）、`crop.cjs`（定格放大）、`diff.cjs`（區域 ΔL*）、`gpucost.cjs`（取消幀率上限的幀時間）。
