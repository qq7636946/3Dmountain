## 第二階段：動態分鏡與時間軸

核心想法（動態導演）：**重的往下、輕的往上。** 水滴受重力滑落離開，帶著的字母因為浮力與慣性被「留在原地」，從水面脫出；字母從水滴離開的那一點開始裂開，碎片沿同一個中心軸螺旋上升。每一步都由前一步造成（因果），而且一個字接一個字（閱讀順序 F → n），不會同時爆開。

章節進度 0–1（與現在的章節時鐘相同）；第 *i* 個字（0–10）的起點 `T(i) = 0.06 + 0.034 × i`。

| 階段 | 時間（章節進度） | 起始狀態 → 結束狀態 | 運動方向與曲線 |
|---|---|---|---|
| ① 靜止 | 0 – 0.06 | 水滴在弧線上、字母完整、輕微漂浮 | 原地緩慢上下（±0.03） |
| ② 鬆動 | T(i) – T(i)+0.09 | 字母在水滴裡因慣性與浮力上移、輕微偏轉（≤0.18 弧度） | sine.inOut；只在水滴內移動 |
| ③ 滑落 | T(i)+0.03 – +0.37 | 水滴從弧線滑落、往畫面深處退去並離開畫面 | power2.in（重力加速）；沿速度方向拉長最多 38%；朝遠離標題的一側（左邊的往左下、右邊的往右下）＋後退 |
| ④ 脫出 | T(i)+0.085 – +0.155 | 字母越過水面、懸在水滴原位上方 0.14；水面鼓起一下，8 顆小水珠被帶起後落回 | power2.out；水珠走拋物線往下（水往下、冰往上） |
| ⑤ 碎裂 | T(i)+0.13 – +0.24 | 先出現髮絲般的裂縫，再從字母**腳下**（水滴離開處）開始，依距離順序一片片鬆脫 | power1.inOut；每片釋放時間依它離裂口的距離排序 |
| ⑥ 螺旋上升 | T(i)+0.14 – +0.66 | 碎片沿同一個中心軸螺旋上升，飛行中放大到 2.3 倍成為畫面主體；細冰粒跟在每片後面 | sine.in（慢起步、漸快）；詳見下節 |
| ⑦A 收攏成字標 | 0.74+0.012i – +0.16 | 碎片依閱讀順序回到字標中各自的位置，接縫完全吻合 → 字標完成 | power3.inOut；收攏時轉正、放大到字標尺寸 |
| ⑦B 向上飄散 | 0.6 起 | 碎片加速上升出畫面、逐漸融進空氣 | 爬升最後 40% 額外 +3、尺寸收到 0 |

**標題與 CTA 的保護：** 碎片只往上走、螺旋最低點在字母原位，螺旋本體在標題上方；滑落的水滴從標題兩側、往深處離開，最多短暫經過，不停留。

## 螺旋軌跡與碎片控制

**碎片怎麼來的。** 每個字母用字標原本的輪廓（保留字形識別），以 Voronoi 分割：種子點有 45% 集中在字母腳下（裂口），所以裂口附近碎、遠處大塊；再用多邊形裁切（polygon-clipping）把字形與每個格子取交集、各自擠出成實心碎片。11 個字共 97 片（每字 6–11 片），F 的品牌藍弧另切 2 片並保留藍色。碎片拼回去時接縫完全吻合，所以裂開前看起來就是完整的字。

**螺旋。** 一條**垂直中心軸**（畫面中線、略在弧線後方）；每片碎片：

| 參數 | 規則 | 目的 |
|---|---|---|
| 起點相位 | 碎片脫離時在中心軸周圍的實際角度 | 從它自己的位置接上螺旋，不跳 |
| 半徑 | 從脫離處的半徑，在上升前 70% 收進自己的環（0.5–1.4），之後隨高度輕微呼吸 ±18% | 漏斗狀收攏成一根清楚的螺旋柱，而不是四散 |
| 轉速 | 全部同一個旋轉方向；每趟 0.9–1.6 圈，小片與內圈較快 | 有速度差但仍是同一個漩渦 |
| 爬升 | 1.45–2.3（小片較輕、爬得較高較快） | 前後錯開 |
| 深度 | 繞軸自然產生前後；後方碎片被空氣淡化 | 前後景深 |
| 翻轉 | 每片自己的軸，大片轉得慢、小片轉得快 | 重量感 |
| 細冰粒 | 每片 3 顆，走**同一條軌跡**、落後 0.025–0.095 | 補細節，但服從整體動態，不是隨機噴發 |

## 第三階段：低成本原型（已完成）

- 獨立頁面，不連到正式網站。three.js r170（與網站同版）、GSAP 3.13 一條時間軸統籌所有階段、捲動帶慣性（0.6 秒追上）。
- 控制：A／B 結尾切換、播放／速度、進度拖桿、顯示螺旋軸與軌跡、細粒子開關；滾輪＝捲動。
- 材質刻意從簡（three.js 內建的玻璃水滴與霜冰），用來驗證「水滴—字母—螺旋」的關係與節奏，不是最後質感。
- 量測（無頭 Chrome＋實體 GPU，桌機 1440×900 與手機模擬 390×844）：全程播放約 75 fps、0 卡頓；97 片碎片、100 次繪製、1.7 萬三角形；無錯誤。手機上弧線兩端會出畫面（與現在的網站相同），字標完整。
