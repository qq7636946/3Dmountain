## 0. 結論

水滴裡裝的是字標的 11 個字母（F-i-n-n-o-v-a-t-i-o-n，F 帶品牌藍弧）。整章就是 LOGO 被一個字一個字組出來：
一串水滴繞著字標連續往上轉（同時在畫面上約 21–27 顆），其中 11 顆帶字母，轉到字標正上方就破開、字母拋起翻身飛進字位；
11 個字到齊時有一拍「成字」（光掃過、字輕輕鼓起、整圈水滴向外一震），之後清水水滴才依序升空離場。

## 0.5 第五輪：動畫導演的調整

回饋：「已經不錯了，但螺旋水滴 LOGO 那段還是不夠好」。逐格審片後的判斷與處理：

| 看到的問題 | 原因 | 調整 |
|---|---|---|
| 螺旋讀起來不像螺旋，下半部像一堆亂飄的泡泡 | 水滴在畫面裡停留兩圈半：過頂之後還繞到字標後方再轉一圈多，和還沒到的水滴混在同一條帶子上、左右對向交錯 | **只留一圈**：水滴從左側凝結 → 從字標下方的後排往右 → 右側上彎 → 上排（正面）往左到字位上方破開 → 左上甩出畫面。過頂之後不再繞回字標後面 |
| 字母送完之後（章節後半）螺旋散掉，只剩零星小珠 | 字母水滴破掉後位置空了，後面接的清水水滴又小又稀 | **整串不斷**：字前、字後各接一段和字母水滴同級的清水水滴（大小有節奏），螺旋的形狀維持到升空為止 |
| 右上角幾顆大水滴疊成一團 | 相鄰水滴間距小於水滴直徑，轉彎處前後重疊 | 整章轉 1 圈 → **1.3 圈**（間距拉開三成，也更有「旋」的感覺）；字母水滴大小差異 0.3 → 0.18；破開時的膨脹 0.3 → 0.16 |
| 字母是「直線掉下去」 | 飛行路徑是直線內插 | **拋起再落下**（飛行拋起）＋途中**側轉翻身、落位轉正**（飛行翻身 26°），冰的側壁會吃到光 |
| 11 個字到齊的那一刻沒有「完成」的感覺 | 掃光只亮在字的側壁（正面只有 5%），其他什麼都沒動 | **成字一拍**：掃光在字的正面也看得到、走完整個字；整個字標鼓起 3.5% 再回來；整圈水滴向外退開 7% 再慢慢收回 |
| 成字和水滴離場擠在一起 | 最後一個字 0.72 到位、0.77 就開始離場 | 最後一個字到位提前到 **0.68**、離場延後到 **0.80**：送字 → 成字 → 離場，各有各的時間 |
| 停手不捲時整圈僵住 | 只有很小的整圈輕晃 | 加一道**慢波**沿著整串往後傳，水滴依序輕輕起伏（靜止時波浪） |

新增的滑桿（都在面板 `L`）：飛行拋起、飛行翻身、成字鼓起、成字水滴外推、靜止時波浪（「節奏與順暢」）；水滴凝結位置、過頂後起飛點、過頂後升空力道（「水滴群」）。
想回到上一版的螺旋形狀：整章轉幾圈 1、水滴凝結位置 1.25、過頂後起飛點 3.14、過頂後升空力道 1。

同時在畫面上的水滴比上一版略少（22–32 → 21–27），但都排在同一條線上，所以看起來更滿、更整齊；想要更多就把「水滴數量」切到「多」。

## 2. 第三輪：為什麼原本「不夠順暢」，改了什麼

**量到的問題。** 用滑鼠滾輪實際捲動時，第二輪每個字「破開」只有 0.10–0.25 秒、「飛入」只有 0.23–0.47 秒——因為這兩段完全綁在捲動位置上，
捲得快就一閃而過，而且字母離開水滴的那一格速度會突然跳一下；螺旋也跟著滾輪一格一格地「走—停—走」。

| | 第二輪 | 第三輪 |
|---|---|---|
| 一個字「破開」的時間（滾輪每秒 2–4 格） | 0.10–0.25 秒，隨捲動快慢變 | 固定 0.54 秒 |
| 一個字「飛入」的時間 | 0.23–0.47 秒，隨捲動快慢變 | 固定 0.81 秒 |
| 字母離開水滴那一格的速度突跳 | 1136 px/s | 55 px/s（幾乎感覺不到） |
| 螺旋轉速的起伏（每秒 2 格滾輪；0＝完全等速） | 0.62 | 0.11 |

**做法。**
- **觸發後照自己的節奏播完。** 水滴轉到破裂點只是「觸發」；破開、飛入、鎖定、整字融合都改成以秒計時，和捲動快慢無關。
  捲得快，幾個字會接連出發、同時在空中，像一串瀑布；捲得慢，一個一個來。往回捲過同一點，整段會倒著播（略快一點）。從選單直接跳進章節則不播動畫、直接是完成的狀態。
- **螺旋有慣性。** 螺旋不再緊貼捲動位置，而是帶重量地跟上（預設 0.8 秒追上）：連續幾格滾輪會變成一段不間斷的轉動，停手後還會滑一小段才停。水滴進場也跟著同一個節奏。
- **字母是「帶著水滴的速度離開」的。** 字母的出發點不是一個固定的位置，而是水滴當下的位置：剛離開時還跟著水滴一起動，再漸漸轉向字位，所以不會有頓一下的感覺；落位只留一點點過衝。
- **靜止時也是活的。** 不捲動時整圈水滴會很慢地來回輕晃。

**水珠的質感。** 水滴裡大部分是清水，所以把清水本身畫好：左上角一塊窗光高光（帶一條窗框）、右下一道細亮弧、
內部不再整顆泛白（原本是為了照片水滴「從裡面發亮」而設計的，清水水滴會顯得霧）、底部的聚光弧更明顯、繞到字標後方的水滴會淡進空氣裡（景深感）。
這些只作用在字母這條路上，照片水滴的樣子沒有變。

## 3. 第二輪回顧（依回饋修改）

| 回饋 | 做法 |
|---|---|
| 字母在水滴裡要小一點 | 字母約佔水滴直徑的 45%（原本約 62%），不在正中央、各自偏一點 |
| 字母要有質感 | 材質重做成「切割過的冰」：邊緣切出斜面（受光側亮、背光側暗）、霜沿著字高結成細針、霜薄的地方看得到後面被折射的房間、冰壁較深較透；字母在水裡投出一道柔和的影子 |
| 多一點水滴，不要一個一個爆破 | 約 30 顆水滴：11 顆帶字母，其餘是大小不一的清水水滴。字母三個一組（Fin・nov・ati・on），每組之間穿插一顆一樣大但**不會破**的水滴 |
| 保持旋轉到最後，像 index2.html | 連續上升螺旋（整章一圈，和 index2 同速）。清水水滴一路轉到章節最後，尾聲一顆接一顆往上轉出畫面 |

## 4. 怎麼做的

**字母在水滴裡是真的 3D，不是貼圖。** 每個字母從 `images/text_logo3.svg` 的同一條輪廓烘成一張 256² 的有號距離場（手機 160²），
水滴的 fragment shader 沿用原本放照片的那套球透鏡光學：視線在水面折射進去，在水裡對「擠出的字母」做光線步進。
所以字母會被水球放大、傾側時看得到側壁、被水染色，轉動時有真實視差。

**冰的質感來自光學。** 光線打到字母後繼續算下去：在字母表面（切邊斜面、霜的粗糙度都算進去）再折一次，
走到水滴另一側、折射出去看到房間——所以霜薄的地方是「透」的。切邊是從距離場直接算出來的。霜針紋理依畫面上的像素大小自動收斂，字母移動時不會閃爍。

**放手之後的字母就是字標本身。** 字標是一塊擠出的玻璃，三角形依字母順序排列；每個字母只是「畫這塊頂點緩衝的其中一段」。
11 個字都到位、霜化完之後，換回原本那一塊字標網格——同一批三角形，所以之後的畫面（含往前衝的轉場）與原版完全相同。
水裡的字母（距離場）和放手後的字母（網格）用同一個著色函式（`ICE_GLSL`），交接不露縫。

**一條螺旋，每顆水滴一個固定位置。** 所有水滴共用同一個轉速；每顆在螺旋上的位置由「它該在什麼時間轉到正面」反推出來。
轉過正面再繞到背後一次之後，螺旋向上張開，水滴就從畫面上緣離開；章節尾聲剩下的水滴用 index2 同一套「加速上升＋多轉一段」離場。
任何兩顆水滴在整章裡都不會互相穿插（有檢查工具）。

## 7. 已知事項

- 因為破開與飛入現在有自己的時間，**捲得非常快**時，字還在飛、章節已經捲過去了；這時剩下的動作會加速收尾（4 倍速），不會卡住，也不影響下一段轉場。
- 首次捲動還有幾個**原本就有**、不在這次範圍內的小停頓：第一段水珠散開時的 shader 編譯（章節時鐘約 −0.55，約 60 ms）、其後一次（約 −0.47，約 15–45 ms），
  以及載入後不久的一次約 22–25 ms（改動前的版本也有）。
- 手機直式畫面比螺旋窄，左右兩側的水滴會出畫面（原本的照片螺旋也是這樣）。
- 進場時水滴從畫面四周飛進螺旋，飛行途中有幾對會短暫擦過彼此（上一版也有，而且更多）；進到螺旋之後整章互不穿插。
- 面板裡你自己調過、存在瀏覽器裡的數值會繼續蓋在新的預設值上；如果想看純粹的第五輪設計值，按面板的「全部還原」。
- 尚未發佈到 GitHub。發佈時記得帶上 `js/water-logo-letters.js` 與 `js/water-logo-letters-panel.js`。
- 只在 Chrome（ANGLE／D3D11）實機驗證；shader 只用 WebGL2 標準語法，Safari／Firefox 未實測。
