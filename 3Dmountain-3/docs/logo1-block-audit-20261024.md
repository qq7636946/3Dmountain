## 3. 方案

### 3.1 LOGO 的呈現方式（三選一）

- A 即時 3D：在海洋的 WebGL 場景內建立 LOGO 1 網格，用同一種玻璃材質，材質可即時調。成本較高，需要把 LOGO 的幾何搬進海洋模組。
- B 預先渲染的旋轉影片：和海面浮水印的做法相同。最省效能、結尾一致，但材質不能即時調，要重算影片。
- C 主場景 LOGO 渲染成貼圖：重用現有材質，但要處理主場景在海洋段是否仍在繪製。
- 建議：A。若效能不夠，再改 B。

### 3.2 旋轉

- 繞垂直軸轉一圈（像轉盤）。結尾自然回到正面，也就是 6.webp 的姿態。
- 旋轉量跟滾動同一個時鐘，滾完最後一格時停在正面。

### 3.3 材質方向

- 保留玻璃折射，加厚圓潤的邊緣（較大的圓角與邊光）。底色貼近海面的藍綠，表面有水的細微起伏。
- 所有參數做成面板，有預設值，可複製參數，和 F5 之後的做法一致。

### 3.4 轉場

- 直接重用海洋段的水波轉場，同一段程式、同一個時鐘。新區塊的起點就是橫移段的最後一格。

### 3.5 團隊

你要求我找專業團隊處理材質。我建議開四個角色的代理：

- 材質：玻璃與水體的 shader、燈光
- 動態：旋轉曲線與結尾停格
- 整合：區塊版型、轉場接點、和海洋段的協調
- 品質：桌機、平板、手機；真實滾輪；效能量測

核准後才開代理。目前只做稽核。
